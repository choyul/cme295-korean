## 1. 강의 개요

- 거대한 LLM으로 많은 토큰을 최대한 효율적으로 생성하는 추론(inference) 단계 기법들을 다룬다.
- 어텐션 층 쪽: KV 캐시(재계산 회피), GQA(키·값 공유), PagedAttention(메모리 단편화 해소), MLA(키·값 압축).
- 출력 토큰 쪽: speculative decoding(작은 모델로 미리 생성)과 multi-token prediction(한 모델 안에 초안 모델 내장).

---

## 2. 학습 목표

1. KV 캐시가 무엇을 재사용하며 왜 키·값만 저장하는지 설명할 수 있다.
2. PagedAttention이 해결하는 메모리 단편화 문제와, MLA가 키·값을 압축하는 발상을 안다.
3. speculative decoding과 multi-token prediction이 작은(또는 내장) 초안 모델로 생성을 가속하는 원리를 이해한다.

### 블록 1 — KV 캐시 (재계산 회피)

**영문 원문**
> (1:27:30) for every token you need the current token to attend to the previous ones (...) in this masked self attention. (...) (1:27:58) you have the query (eats). You will compute the key representation and the value representation of (eats) (...) But we want to (...) reuse the past computations (...) (1:28:58) we want (...) the key and value matrices to be saved (...) the query corresponding to the previous tokens are not going to be of interest for the present token. (...) (1:28:58) this concept of KV cache where the goal is to store these key and value matrices (...) and reuse them directly from the cache. (...) (1:29:33) during training (...) teacher forcing (...) this concept of KV caching doesn't even come up.

**한국어 번역**
마스크드 self-attention에서, 현재 토큰은 그 앞의 토큰들에 어텐션해야 합니다. 예를 들어 "a cute teddy bear"를 생성했고 지금 "is"를 처리한다면, "is"의 쿼리·키·값은 당연히 새로 계산합니다. 그런데 앞 토큰들의 키·값 표현은 이미 전에 계산했으니, 그 과거 계산을 재사용하고 싶습니다.

즉 키 행렬과 값 행렬을 저장해 두려는 것입니다. (쿼리는 저장하지 않습니다 — 앞 토큰들의 쿼리는 현재 토큰 예측에 필요 없기 때문입니다.) 이 장치가 KV 캐시(KV cache)입니다. 키·값 행렬을 어딘가 저장해 두고, 새 토큰을 계산할 때 다시 계산하지 않고 캐시에서 바로 가져옵니다.

> 학습 때는? 학습에서는 교사 강요(teacher forcing)로 입력을 한꺼번에 넣고 처리하므로, KV 캐싱 개념 자체가 등장하지 않습니다. (KV 캐시는 추론 단계의 기법)

**용어 설명**
- **추론(inference)**: 학습된 모델로 실제 생성을 수행하는 단계.
- **KV 캐시(KV cache)**: 앞 토큰들의 키·값을 저장해 재계산을 피하는 장치. 키·값만 저장(쿼리는 제외).
- **마스크드 self-attention**: 현재 토큰이 자기와 앞 토큰만 보는 어텐션(decoder-only).

(1:31:28) you're attending to everyone and you focus on the number of keys and values. Is there a way to reduce this number? (...) (1:31:56) group query attention (...) we had this concept of grouping keys and values together (...) the general formulation is called group query attention where you group these (...) in modern day LLM's a lot of papers they use GQA.

**한국어 번역**
지난 강의(Lecture 2)에서 캐시 양, 즉 키·값을 줄일 수 있는 기법을 재사용할 수 있을까요? 멀티헤드 어텐션에서는 H개 헤드마다 쿼리·키·값 투영이 따로 있습니다. 키·값 투영의 개수를 줄일 방법 — 바로 GQA(Grouped-Query Attention, 그룹 쿼리 어텐션)입니다. 키·값을 그룹으로 묶어 공유하는 것으로(H개와 1개의 양 극단이 각각 표준 멀티헤드와 MQA), 현대 LLM의 많은 논문이 적절한 그룹 수로 GQA를 씁니다. 키·값을 공유하면 저장할 키·값이 줄어 KV 캐시가 작아집니다.

**용어 설명**
- **GQA(Grouped-Query Attention)**: 키·값 투영을 그룹별로 공유. KV 캐시 크기를 줄임. (Lecture 2 섹션 3 참고)

### 블록 3 — PagedAttention (메모리 단편화 해소)

**영문 원문**
> (1:32:37) the hardware side (...) (1:33:23) a naive way of storing the key and value matrices would be reserving a portion of the memory (...) that correspond(s) to the entire context length (...) you stop your decoding when you hit the EOS token (...) it leads to a lot of waste. (...) (1:34:32) paged (at)tention (...) reserved (...) internal fragmentation and external fragmentation (...) (1:35:39) it breaks it down by smaller chunks (...) a value of 16 for blocks (...) some dictionary that maps token position indices to their cache values (...) it reduces fragmentation by quite a lot.

**한국어 번역**
이제 하드웨어 쪽입니다. 추론 서버가 여러 사용자의 요청을 받는다고 합시다. KV 캐시를 순진하게 저장하면, 처음에 전체 컨텍스트 길이만큼의 메모리를 미리 예약해 둡니다 — 디코딩이 EOS 토큰에서 언제 멈출지 모르기 때문입니다. 예컨대 컨텍스트 길이가 2,000이면 요청마다 2,000칸을 예약합니다. 이건 낭비가 큽니다. 요청이 늘면 메모리가 금방 부족해집니다.

PagedAttention 논문이 이를 해결했습니다. 몇 가지 개념을 정의합니다 — 예약(reserved), 내부 단편화(internal fragmentation), 외부 단편화(external fragmentation). 내부 단편화는 요청 완료용으로 예약했지만 실제로는 안 쓰인 빈 공간이고, 외부 단편화는 메모리 관리 시스템이 블록을 띄엄띄엄 할당해 생기는 틈입니다. PagedAttention은 생성 과정을 고정 크기 블록(논문은 블록당 16) 단위로 매핑합니다. 메모리를 통째로 예약하는 대신 작은 덩어리로 쪼개 쓰고, 토큰 위치 인덱스를 그 캐시 값에 매핑하는 사전(dictionary)을 둡니다. 이 방식(추론 패키지 vLLM에 적용)이 단편화를 크게 줄였습니다.

**용어 설명**
- **PagedAttention**: KV 캐시 메모리를 고정 크기 블록으로 쪼개 관리해 낭비를 줄이는 기법.
- **메모리 단편화(fragmentation)**: 메모리에 쓸모없는 빈틈이 생기는 것. 내부(예약 후 미사용)·외부(할당 틈)로 나뉨.
- **vLLM**: PagedAttention을 적용한 추론 패키지(소프트웨어).
- **EOS 토큰**: 생성을 멈추는 끝 표시 토큰.

### 블록 4 — MLA: 키·값 압축 (DeepSeek)

**영문 원문**
> (1:36:36) key and value is (...) of a dimension that is non-negligible and you need to store each copies of it in each transformer block (...) is there a way to make that representation more compact (...) DeepS(eek) (...) multi-l(atent) attention. (...) (1:38:09) what multi-l(atent) attention does is that it factorizes these projection matrix into an intermediary space that is of lower dimension than the space of keys (...) reduces the dimension and then another one that decompresses it. (...) (1:38:44) the compression matrix could be shared across keys and values (...) (1:39:16) even better share it across the h heads (...) for every transformer block you have a single representation per token. (...) (1:39:54) the deep se(ek)v2 paper also showed a performance improvement (...) credited (to) some regularization.

**한국어 번역**
키와 값은 차원이 작지 않고, 트랜스포머 블록마다 그 사본을 저장해야 합니다. 저장할 벡터가 매우 많고 또 길죠. 이를 더 압축할 수 없을까요? DeepSeek이 MLA(Multi-head Latent Attention, 다중 잠재 어텐션)로 다룬 주제입니다.

기본 멀티헤드에서는 토큰 표현을 키로 만드는 투영 행렬 W_k가 헤드마다(H개) 있고, 결과 임베딩도 H개를 캐시에 저장해야 합니다(값도 마찬가지). MLA는 이 투영 행렬을 키 공간보다 낮은 차원의 중간 공간으로 인수분해(factorize)합니다 — 먼저 차원을 줄이는 변환, 그다음 복원(압축 해제)하는 변환을 둡니다. 그래서 캐시에는 줄어든(압축된) 표현만 저장하면 됩니다.

더 영리한 점:
- 압축 행렬을 키·값이 공유합니다 — 한 토큰에 대해 키·값용으로 저장할 캐시가 같아집니다(복원 행렬은 키·값 각각 따로 둬서 서로 다른 표현은 학습).
- 나아가 H개 헤드에 걸쳐서도 공유합니다 — H개 임베딩 대신 단 하나만 둡니다. 그래서 트랜스포머 블록마다 토큰당 표현이 하나로 줄어듭니다.

DeepSeek-V2 논문은 저장량을 줄였을 뿐 아니라 성능 향상도 보였는데, 이는 일종의 정규화(regularization) 효과로 해석됩니다 — 키·값에 걸쳐 공유된, 더 유용한 표현을 학습한다는 것입니다. (압축 중간 차원은 설계 선택으로 고정값)

**용어 설명**
- **MLA(Multi-head Latent Attention, 다중 잠재 어텐션)**: 키·값을 낮은 차원으로 압축해 KV 캐시를 줄이는 기법(DeepSeek).
- **인수분해/압축(factorize)**: 큰 투영을 '차원 축소 → 복원' 두 단계로 나눔.
- **정규화(regularization)**: 모델이 더 일반화되게 만드는 효과. MLA의 부수 이점.

### 블록 5 — Speculative decoding (작은 초안 모델로 가속)

**영문 원문**
> (1:41:28) techniques that operate at the output token level (...) speculative dec(oding) (...) uses some smaller model to help the generation of a bigger model (...) (1:42:26) you ask a smaller model (...) the paper calls draft to generate next words (...) since the LLM is small this is typically done faster (...) (1:42:54) you put the tokens that are predicted by the smaller LLM all as input to the target LLM (...) (1:43:38) if the probability of the draft model is bigger (...) you just accept the token. Otherwise you have some acceptance rejection mechanism (...) (1:44:13) if everything is accepted then in a single pass you were able to advance by way more tokens (...) (1:45:51) at inference time you are memory bound (...) computations are not the limiting factor.

**한국어 번역**
이제 출력 토큰 단위의 기법입니다. 첫째는 speculative decoding(추측 디코딩)으로, 작은 모델을 써서 큰 모델의 생성을 돕되, 출력 분포가 큰(목표) 모델의 것과 일치하도록 보장하는 영리한 방법입니다.

방식: 작은 모델(논문에서 draft, 초안 모델이라 부름)에게 다음 단어들을 먼저 생성시킵니다. 예를 들어 "my teddy bear" 다음에 "is", "cute", "smart"를 작은 모델이 빠르게 이어 냅니다(작아서 빠름). 그다음 이 초안 토큰들을 한꺼번에 목표(큰) 모델에 입력으로 넣어, 각 토큰의 확률 분포를 얻습니다. 그리고 수락-기각(acceptance-rejection) 규칙을 적용합니다 — 초안 모델이 예측한 토큰의 확률이 (조건을 만족하면) 수락하고, 아니면 기각해 그 지점부터 분포를 보정하며 다시 생성합니다. 전부 수락되면 한 번의 패스로 여러 토큰을 한꺼번에 진전시킬 수 있습니다.

왜 목표 분포와 일치하나: 전체 확률의 법칙(law of total probability)에서 출발해 각 항을 전개하면 목표 분포가 나옵니다(논문에 몇 줄로 증명 — 일종의 기각 샘플링rejection sampling). 또 초안 토큰들과 함께 마지막 토큰까지 넣는 이유는, 한 번의 순전파로 그 다음 토큰의 분포까지 공짜로 얻어 바로 샘플링할 수 있기 때문입니다.

핵심 직관: 추론 시에는 연산이 아니라 메모리가 병목(memory bound)입니다. 그래서 작은 모델로 토큰들을 미리 뽑고, 큰 모델로는 그 모든 분포를 한 번에 계산하는 게 유리합니다. (한 번에 여러 토큰을 넣어 계산하는 비용이 한 토큰씩 여러 번 하는 것과 비슷하기 때문)

**용어 설명**
- **speculative decoding(추측 디코딩)**: 작은 초안 모델로 토큰을 미리 생성하고, 큰 모델이 한 번에 검증·수락해 생성을 가속.
- **초안 모델(draft model)**: 빠르게 후보 토큰을 내는 작은 모델.
- **수락-기각(acceptance-rejection)**: 초안 토큰을 받아들일지 정하는 규칙. 목표 분포와 일치 보장(기각 샘플링).
- **메모리 병목(memory bound)**: 추론 속도를 제한하는 것이 연산이 아니라 메모리라는 사실.

### 블록 6 — Multi-token prediction (초안 모델 내장)

**영문 원문**
> (1:46:49) multi-token prediction (...) doing the same but (...) the draft model is embedded in the same model (...) (1:47:16) a model that attaches multiple heads on top of the representation of the last decoder (...) at training time, it doesn't do next word prediction. It does multi-word prediction. And at test time, the draft model is all your heads. And your main model is just the first head(s). (...) (1:47:45) the paper does it in a greedy way (...) the interesting note (...) is the change in objective function (...) the draft model and the target model are basically embedded in the same one.

**한국어 번역**
마지막은 multi-token prediction(다중 토큰 예측)입니다. speculative decoding과 같은 일을 하되, 초안 모델을 별도로 두지 않고 같은 모델 안에 내장하는 강력한 방식입니다.

마지막 디코더의 표현 위에 여러 개의 헤드(head)를 붙입니다. 학습 때 다음 단어 예측이 아니라 다중 단어 예측(여러 다음 토큰을 동시에 예측)을 합니다. 테스트(추론) 때는 — 이 여러 헤드가 곧 초안 모델 역할을 하고, 첫 번째 헤드가 본 모델 역할을 합니다. 즉 헤드들이 만든 초안 토큰들을 다시 첫 헤드에 넣어 수락-기각을 합니다. (논문은 그리디 방식으로 수행 — 목적함수가 바뀌어 speculative decoding의 깔끔한 분포 일치 성질 대신 약간 변형된 형태를 씀)

핵심 포인트 두 가지: ① 목적함수가 바뀐다(다음 토큰 예측 → 다중 토큰 예측), ② 초안 모델과 목표 모델이 같은 모델에 내장돼 둘을 분리할 필요가 없다.

> 강사 마무리: 이번 강의에서 본 효율화 기법들은 각각 추론의 서로 다른 측면(어텐션·메모리·출력 생성)을 개선합니다. 관련 논문들을 직접 보길 권합니다.

**용어 설명**
- **multi-token prediction(다중 토큰 예측)**: 한 모델에 여러 헤드를 붙여 여러 다음 토큰을 예측. 초안 모델을 내장.
- **헤드(head)**: 여기서는 마지막 디코더 표현 위에 붙인 출력 갈래. 각각 다른 미래 토큰 예측.
- **목적함수 변경**: 다음 토큰 예측 → 다중 토큰 예측으로 학습 목표를 바꿈.

## 부록. 실무 적용 포인트 (NLP·LLM 기술 내용 한정)

- **이 기법들은 모두 "왜 LLM 서비스 비용·속도가 그렇게 결정되는가"의 내부 사정이다.** KV 캐시·PagedAttention·MLA는 메모리를, speculative/multi-token은 생성 속도를 다룬다. 정책담당자가 코드를 짤 일은 없지만, AI 서비스 요금·응답속도가 '연산'만이 아니라 '메모리 관리'와 '디코딩 방식'에 크게 좌우된다는 큰 그림을 알면 도입·계약 시 판단에 도움이 된다.
- **메모리가 병목이라는 사실은 "긴 대화·긴 출력이 왜 무거워지는가"를 설명한다.** 생성이 길어질수록 KV 캐시가 쌓여 메모리를 잡아먹는다. 긴 세션이 느려지거나 비용이 오르는 배경이며, GQA·MLA 같은 기법이 이를 얼마나 적용했는지가 모델별 효율 차이를 만든다.
- **speculative decoding은 "작은 모델 + 큰 모델 조합"이라는 비용 절감 발상의 한 예다.** 빠른 작은 모델이 초안을, 정확한 큰 모델이 검증을 맡는 구조다. 직접 구축할 일은 드물지만, 'AI 비용은 모델 하나의 크기만이 아니라 조합·구조로도 줄일 수 있다'는 관점을 얻을 수 있다.
