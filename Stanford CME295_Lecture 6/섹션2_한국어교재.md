## 3. 본문

### 블록 1 — 추론(reasoning)이란

**영문 원문**
> (13:18) there's not a commonly agreed upon definition (...) we define reasoning as the ability to solve a problem (...) typically (...) math problems or (...) coding problems (...) (14:24) a multi-step reasoning process (...) (14:52) a non-reasoning question would be (...) what is the course code of Stanford's transformers (...) class (...) CME 295 (...) a reasoning based question would be (...) a bear that was born in 2020. How old is that bear now in 2025?

**한국어 번역**
'추론(reasoning)'에는 합의된 정의가 없습니다. 강사는 추론을 '문제를 푸는 능력'으로 정의합니다. 여기서 문제는 주로 수학·코딩 문제를 떠올리지만, 다른 분야로도 퍼질 수 있습니다. 추론 문제는 보통 다단계 추론 과정(multi-step reasoning)을 거칩니다 — 시험에서 자명하지 않은 문제를 여러 단계로 쪼개 풀어 답에 이르듯이.

예시로 구분하면:
- **비추론 질문**: "스탠퍼드 트랜스포머·LLM 수업의 과목 코드는?" → CME 295. 단순 지식.
- **추론 질문**: "2020년에 태어난 곰이 2025년에 몇 살인가?" → 계산(단계)이 필요. (물론 더 어려운 것도 가능)

**용어 설명**
- **추론(reasoning)**: 문제를 (다단계로) 푸는 능력. 합의된 정의는 없음.
- **다단계 추론(multi-step reasoning)**: 문제를 여러 단계로 쪼개 풀어가는 과정.
- **추론 vs 비추론 질문**: 계산·논리가 필요한 문제 vs 단순 지식 조회.

### 블록 2 — 사고연쇄(chain of thought)의 대규모화

**영문 원문**
> (15:59) leverage a concept (...) chain of thought (...) thinking in steps (...) instead of just giving (...) a blanket answer. (...) (18:35) in context learning examples that explicited the reasoning (...) (19:08) if you have a very hard problem (...) there are very few chances that that problem appeared in the training set (...) decompose the problem into tractable (steps) (...) rely on the patterns that it has seen during training. (...) (20:41) when you let the LLM generate more you're just giving it more compute (...) compute budget(s).

**한국어 번역**
추론 모델의 핵심 아이디어는 앞서(2~3강) 본 사고연쇄(chain of thought, CoT)를 활용하는 것입니다. CoT란 한 번에 답을 던지지 않고 단계적으로 생각하는 것입니다. 원래 CoT는 인컨텍스트 러닝 예시에 추론 과정을 명시해 모델이 답 전에 추론하도록 유도했습니다. 추론 모델은 이를 훨씬 큰 규모로 합니다.

왜 도움이 되나(직관 두 가지):
1. **문제 분해 + 패턴 활용**: LLM은 다음 토큰 예측으로 학습됩니다. 아주 어려운 문제는 학습 데이터에 거의 없습니다. 그래서 문제를 다루기 쉬운(tractable) 작은 단계들로 분해하고, 학습 때 본 패턴으로 그 작은 문제들을 풉니다. (학생이 어려운 문제를 아는 것에 연결해 푸는 것과 같음)
2. **추가 연산(compute)**: 더 많이 생성하게 하면 생성 단계마다 순전파가 일어나니 연산을 더 주는 셈입니다. '연산 예산(compute budget)'이라는 개념으로 뒤에서 다룹니다.

그래서 추론 모델은 질문을 받으면 곧바로 답하지 않고, **먼저 추론 사슬(reasoning chain)을 출력한 뒤 답**합니다. 출력 = 추론 + 답.

**용어 설명**
- **사고연쇄(chain of thought, CoT)**: 답 전에 단계적 추론을 펼치는 것.
- **문제 분해(decompose)**: 어려운 문제를 다루기 쉬운 작은 단계로 나눔.
- **연산 예산(compute budget)**: 응답 생성에 쓸 연산량(=생성 길이). 많이 생각할수록 연산↑.
- **추론 사슬(reasoning chain)**: 답에 이르는 추론 과정. 추론 모델은 이를 답 앞에 출력.

### 블록 3 — 타임라인·UI·과금

**영문 원문**
> (22:20) reasoning models have started popping out starting from OpenAI's release of (o)1 preview (...) September of (2024) (...) Google's Gemini 2.0 flash thinking (...) December (...) DeepS(eek) R1 paper (...) January (2025) (...) match OpenAI's reasoning (...) performance. (...) (24:29) the key word here is thinking (...) (25:31) the thought (...) summary (...) is not the raw reasoning chain (...) (26:37) you're actually getting charged for it (...) output tokens (...) include reasoning tokens.

**한국어 번역**
**타임라인**: 추론 자체는 오래된 주제지만 '추론 모델'은 최근 1년의 일입니다. OpenAI의 o1-preview(2024년 9월)로 시작해, 다른 AI 연구소들이 "어떻게 했나" 궁금해하며 뛰어들었습니다. 구글 Gemini 2.0 Flash Thinking(12월), 그리고 2025년 1월 DeepSeek-R1 논문이 큰 반향을 일으켰습니다 — OpenAI의 추론 성능을 논문에 방법까지 기술하며 따라잡았기 때문입니다. 이후 xAI·Anthropic(Claude)·Mistral 등도 추론 능력을 추가했습니다. 핵심은 — 이 흐름이 2024년 말 시작됐다는 점입니다.

**UI 표시**: 챗봇이 추론 모델인지 알려면 'thinking(생각 중)' 표시를 봅니다. UI는 전체 추론 과정을 보여주지 않고 '생각하는 데 쓴 시간'을 표시하며, 보여주는 '생각 요약'은 원본 추론 사슬이 아니라 요약입니다. 원본을 안 보여주는 이유(추정): ① 원본이 사람이 읽기엔 불완전할 수 있고, ② 사용자가 긴 글을 다 읽고 싶지 않으며, ③ 원본 추론 사슬이 있으면 다른 모델이 그걸로 학습해 능력을 흉내 낼 수 있어서.

**과금**: 추론 모델의 출력은 답 + 추론입니다. API는 출력 토큰으로 과금하는데, 이 출력 토큰에 추론 토큰(reasoning token)이 포함됩니다. 즉 추론도 돈을 냅니다. 그래서 사용자는 '최소 추론 토큰으로 최대 추론력'을 원하게 됩니다.

**용어 설명**
- **o1-preview / DeepSeek-R1**: 추론 모델의 초기 대표(2024.9 / 2025.1). R1은 방법을 공개해 반향.
- **thinking 표시**: 추론 모델이 생각하는 시간을 보여주는 UI 신호.
- **추론 토큰(reasoning token)**: 추론 사슬을 이루는 출력 토큰. 과금 대상.

## 부록. 실무 적용 포인트 (NLP·LLM 기술 내용 한정)

- **사고연쇄는 "단계적으로 생각하라고 시키면 더 잘 푼다"는, 누구나 쓰는 프롬프트 기법이다.** 추론 모델이 아니어도, 복잡한 계산·판단 업무에 "근거를 단계별로 들어 설명한 뒤 답하라"고 지시하면 정확도가 오른다(Lecture 3 CoT와 연결). 보조금 산정·조건 판단처럼 다단계가 걸린 행정 업무에 유용하다.
- **추론 토큰 과금은 "추론 모델은 더 비싸고 느리다"는 비용 현실을 알려준다.** 추론 모델은 답 외에 긴 사고 과정까지 생성·과금된다. 단순 작성·요약에는 일반 모델이, 복잡한 추론에는 추론 모델이 합리적이다 — 업무 성격에 따라 모델을 나눠 쓰면 비용을 아낄 수 있다.
- **'thinking' 표시로 추론 모델 여부를 구분하는 안목**은 도구 선택에 직접 쓰인다. 같은 챗봇이라도 추론 모드를 켜면 더 정확하지만 느리고 비싸다. 작업 난이도에 맞춰 추론 모드를 켜고 끄는 판단이 효율을 좌우한다.
