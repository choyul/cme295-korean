## 3. 본문

### 블록 1 — 텍스트 처리부터 self-attention까지 (Lecture 1)

**영문 원문**
> (01:46) tokenization (...) dividing the input into atomic units (...) subword level tokenizer. (...) (02:49) wordtovec (...) learned from a proxy task (...) not context(-)aware (...) (03:21) RNN's (...) long range dependency (...) (04:21) self attention where tokens can (...) attend to one another regardless of where they are placed (...) query, key and value (...) soft max of q k(transpose) over square root of dk (...) v.

**한국어 번역**
한 줄기로 복습합니다.
- **토큰화(Lecture 1)**: 입력을 원자 단위(토큰)로 나눔. 가장 흔한 건 서브워드 토크나이저(어근 재활용).
- **임베딩**: word2vec은 대리 과제(주변/중심 단어 예측)로 표현을 학습. 한계 — 맥락 비의존(같은 단어가 어느 문장에서나 같은 표현).
- **RNN**: 토큰을 하나씩 처리하며 내부 표현 유지. 한계 — 장기 의존성(먼 과거를 못 기억).
- **self-attention**: 위치와 무관하게 토큰이 서로에 주의(직접 연결). 쿼리·키·값으로, softmax(QKᵀ/√dₖ)·V 공식. 오늘날 하드웨어에 잘 맞는 효율적 행렬 연산.
- **트랜스포머**: 인코더(왼쪽)·디코더(오른쪽). 번역에서 출발.

**용어 설명**
- (Lecture 1~3 섹션 참고) 토큰화·임베딩·RNN·self-attention·트랜스포머.

### 블록 2 — 트랜스포머 개선과 파생 모델 (Lecture 2)

**영문 원문**
> (07:27) rotary position embeddings aka rope (...) rotates query and keys (...) a function of the relative distance. (...) (08:29) group query attention (...) (09:01) postnorm (...) prenorm. (...) (10:03) birds (...) encoder only (...) CLS token (...) GPT (...) decoder only (...) T5 (...) both.

**한국어 번역**
트랜스포머(2017) 이후 개선(Lecture 2):
- **위치 인코딩 → RoPE**: 원논문은 절대 위치 임베딩이었으나, 중요한 건 상대 위치. RoPE(회전 위치 임베딩)는 쿼리·키를 회전시켜 상대 거리만 반영하며, self-attention 층에서 작동.
- **GQA(그룹 쿼리 어텐션)**: 헤드마다 키·값 투영을 따로 두지 않고 묶어 공유.
- **정규화 위치**: post-norm → pre-norm(요즘은 하위 층 앞에 정규화).

파생 모델: 인코더만 = BERT(분류용 CLS 임베딩), 디코더만 = GPT, 둘 다 = T5. encoder-only는 텍스트 생성 못 하고 임베딩 생성(다운스트림용), encoder-decoder·decoder-only는 자기회귀로 텍스트 생성.

**용어 설명**
- RoPE / GQA / pre-norm / BERT·GPT·T5: Lecture 2 섹션 참고.

### 블록 3 — LLM: MoE와 디코딩 (Lecture 3)

**영문 원문**
> (11:08) large language models (...) decoder only transformer-based (...) (11:37) mixture of experts (...) activate (...) a subset (...) in the feed for(ward) neural network layer (...) a gating mechanism (...) (13:48) sample from the output distribution (...) greedy (...) temperature (...) spiky (...) more deterministic (...) higher temperatures (...) more creative.

**한국어 번역**
LLM은 decoder-only 트랜스포머 기반 텍스트→텍스트 모델입니다. 스케일을 키우면서 새 기법들이 나왔습니다(Lecture 3):
- **전문가 혼합(MoE)**: 전체를 다 돌리지 않고 일부 전문가만 희소하게 활성화. FFN 층에 두고, 게이팅이 토큰을 적절한 전문가(FFN)로 라우팅. 토큰 단위 라우팅이라 GPU 분산도 용이.
- **디코딩**: 다음 토큰 확률 분포에서 샘플링. 최고 확률만 고르는 그리디 대신 샘플링으로 다양성 부여. 온도(temperature)로 조절 — 낮으면 뾰족(결정적), 높으면 다양·창의적.

**용어 설명**
- MoE / 게이팅 / 온도: Lecture 3 섹션 참고.

## 4. 핵심 용어집

| 영문 | 한국어 | 뜻 |
|---|---|---|
| tokenization / subword | 토큰화/서브워드 | 입력을 토큰으로 나눔 |
| word2vec | 워드투벡 | 대리 과제로 임베딩 학습 |

| pre-norm | 프리놈 | 하위 층 앞 정규화 |
| BERT/GPT/T5 | — | 인코더/디코더/둘 다 |
| MoE | 전문가 혼합 | 일부 전문가만 활성화 |
| temperature | 온도 | 샘플링 다양성 조절 |

## 부록. 실무 적용 포인트 (NLP·LLM 기술 내용 한정)

- **이 복습은 "LLM 한 줄기 지도"다.** 텍스트를 잘라(토큰화) 숫자로 바꾸고(임베딩), 서로 연결해(self-attention) 처리하는 흐름을 알면, AI가 글을 다루는 원리를 큰 틀에서 이해할 수 있다. 도구를 고르고 한계를 가늠하는 모든 판단의 토대다.
- **MoE·온도는 즉시 쓰는 실무 지식이다.** "큰 모델인데 왜 빠른가(MoE)", "온도를 낮추면 일관, 높이면 창의"는 모델 선택·설정에 바로 적용된다(앞 강의 부록들과 연결).
