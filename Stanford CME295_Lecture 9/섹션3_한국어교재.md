## 3. 본문

### 블록 1 — RAG (Lecture 7)

**영문 원문**
> (38:53) rag (...) retrieval augmented generation (...) fetch relevant documents (...) knowledge cut(off) (...) (40:29) candidate retrieval (...) by encoder (...) semantic search (...) cosign similarity (...) (41:33) cross encoder (...) more precise score (...) top (...) K (...) augmented (...) generate.

**한국어 번역**
**RAG(검색 증강 생성)**: 지식 베이스에서 관련 문서를 찾아 프롬프트에 넣어 답하게 함(Lecture 7). 필요 이유 — LLM 지식은 컷오프까지로 한정되고, 모델을 매일 재학습하지 않으니, 최신·미학습 정보가 필요할 때 외부 접근이 유용. 검색은 2단계:
1. **후보 검색(candidate retrieval)**: bi-encoder로 의미 검색 — 질의 임베딩과 미리 계산한 문서 임베딩의 코사인 유사도로 후보를 추림.
2. **랭킹/재랭킹**: cross-encoder(질의·문서를 함께 모델에 넣음)로 더 정밀한 점수를 내 상위 K를 선택.

상위 K를 프롬프트에 넣고(augment) 생성(generate)합니다. (강사: RAG는 면접·시험에도 중요한 핵심 개념)

**용어 설명**
- RAG/후보 검색/bi·cross-encoder: Lecture 7 섹션 참고.

### 블록 2 — 도구 호출과 에이전트 (Lecture 7)

**영문 원문**
> (42:43) tool calling (...) two steps (...) which API (...) with these arguments (...) run your API (...) feed the results (...) back to the LLM. (...) (43:42) agentic workflows (...) leveraging both rag and tool calling (...) a series of different calls (...) returns an answer.

**한국어 번역**
**도구 호출(tool calling)**: LLM이 도구(API)를 쓰게 함. 2단계 — ① LLM이 어떤 API를 어떤 인자로 쓸지 정함(중간에 실제 API 실행), ② 실행 결과를 다시 LLM에 줘 최종 답 생성.

**에이전트 워크플로**: RAG와 도구 호출을 핵심 수단으로 결합. 입력에 대해 LLM이 여러 번 호출을 거쳐 행동을 수행하고 끝에 답을 반환(ReAct 등).

**용어 설명**
- 도구 호출/에이전트: Lecture 7 섹션 참고.

### 블록 3 — 평가와 시험 범위 (Lecture 8)

**영문 원문**
> (44:13) evaluate LLMs (...) rulebased metrics (...) blur, rouge, me(t)or (...) not considering how language could differ (...) (44:44) LLM as a judge (...) prompt(s) (...) response (...) criteria (...) rationale (...) score (...) (46:17) position bias (...) verbosity bias (...) self-enhancement bias. (...) (48:20) for the final (...) 5 6 7 8.

**한국어 번역**
**평가(Lecture 8)**: LLM이 다양한 일을 하게 되며 평가가 어려워짐.
- **규칙 기반 지표**: BLEU·ROUGE·METEOR 등. 한계 — 표현이 달라도 같은 뜻인 경우를 못 봄.
- **LLM as a judge**: 프롬프트+응답+기준을 입력받아, 점수(보통 이진)와 근거(rationale)를 출력. 근거를 점수보다 먼저 출력하면 성능↑(추론 모델의 사고연쇄와 같은 원리).
- **편향**: 위치 편향(먼저 제시된 것 선호), 장황함 편향(긴 것 선호), 자기선호 편향(자기 출력 선호).
- 그 외 모델 비교용 벤치마크(지식·추론·코딩·안전 등).

**기말 시험 범위**: Lecture 5~6~7~8 (중간은 1~4였음). 이후(트렌드·마무리)는 시험 범위 아님.

**용어 설명**
- 규칙 기반 지표/LLM as a judge/편향: Lecture 8 섹션 참고.

## 4. 핵심 용어집

| 영문 | 한국어 | 뜻 |
|---|---|---|
| RAG | 검색 증강 생성 | 관련 문서 검색해 프롬프트 보강 |
| candidate retrieval / ranking | 후보 검색/랭킹 | bi-encoder 추림 / cross-encoder 정밀 |
| tool calling | 도구 호출 | LLM이 API 사용(2단계) |
| agentic workflow | 에이전트 워크플로 | RAG+도구 호출, 여러 호출 |
| LLM as a judge | LLM 심판 | 점수+근거로 평가 |
| position/verbosity/self-enhancement bias | 위치/장황함/자기선호 편향 | 심판의 세 편향 |

## 부록. 실무 적용 포인트 (NLP·LLM 기술 내용 한정)

- **RAG·도구·에이전트는 "LLM을 실무 시스템에 붙이는 3대 수단"이다.** 최신·내부 자료 주입(RAG), 시스템·계산 연동(도구), 다단계 자동화(에이전트). 봉화군 업무에 AI를 실제로 엮는 길의 핵심 묶음이다(Lecture 7 부록과 연결).
- **평가는 "도입 효과를 확인하는 마지막 관문"이다.** 단어 일치(규칙 기반)로는 부족하고, LLM 심판은 편향을 안고 있으니, 결국 자기 업무 샘플로 직접 점검하는 것이 가장 확실하다(Lecture 8 부록과 연결).
