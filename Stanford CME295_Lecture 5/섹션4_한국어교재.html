섹션 4. 보상 모델 (Bradley-Terry와 손실 함수)

📄원문 출처: Stanford CME295, Autumn 2025, Lecture 5, 타임스탬프 28:33~46:03

1. 강의 개요

  • RLHF의 첫 단계인 보상 모델(reward model)을 만드는 법 — 좋은/나쁜 응답에 점수를 매기는 모델을 다룬다.
  • 두 응답의 우열 확률을 점수로 표현하는 Bradley-Terry 공식과, 거기서 손실 함수를 유도하는 과정을 본다.
  • 보상 모델이 쌍 비교로 학습되지만 추론 때는 응답 하나에 점수 하나를 내는 점, 모델 선택·정규화를 설명한다.

2. 학습 목표

  1. 보상 모델이 (프롬프트+응답)을 받아 점수를 내는 모델임을 안다.
  2. Bradley-Terry 공식과 시그모이드(sigmoid)로 우열 확률을 표현하고, 음의 로그우도로 손실을 유도할 수 있다.
  3. 보상 모델이 쌍 비교로 학습되지만 추론은 점수 하나를 낸다는 점, 보상이 차원·정규화에 의존함을 이해한다.

3. 본문

한국어 번역

보상 모델(reward model, RM)은 어떤 출력이 좋고 나쁜지를 아는 모델입니다. 응답만이 아니라 프롬프트도 함께 봐야 합니다(맥락이 필요하므로). 예를 들어 "곰인형과 할 새 활동을 제안해줘"라는 프롬프트에 대해, 좋은 응답에는 높은 점수를, 나쁜 응답에는 낮은 점수를 내는 모델을 원합니다.

이를 만드는 데 쓰는 것이 Bradley-Terry 공식입니다. 출력 yᵢ가 yⱼ보다 나을 확률을:

P(yᵢ > yⱼ) = exp(Rᵢ) / (exp(Rᵢ) + exp(Rⱼ)) = σ(Rᵢ − Rⱼ)

로 둡니다. 여기서 σ는 시그모이드(sigmoid), 즉 σ(x) = 1/(1+exp(−x))입니다. 시그모이드는 입력이 −∞면 0, +∞면 1에 가까워집니다. 따라서 i가 j보다 나으면 σ의 입력(Rᵢ−Rⱼ)이 크길 원합니다 — 즉 좋은 출력 i의 점수 Rᵢ는 높게, 나쁜 출력 j의 점수 Rⱼ는 낮게 만들고 싶습니다.

용어 설명
보상 모델(reward model, RM)
(프롬프트+응답)을 받아 좋음/나쁨 점수를 내는 모델.
Bradley-Terry 공식
두 항목의 우열 확률을 각 점수의 지수비로 표현하는 식.
시그모이드(sigmoid, σ)
값을 0~1로 누르는 함수. σ(x)=1/(1+e⁻ˣ).

한국어 번역

학습은 이렇게 합니다. 모델을 초기화하고, 한쪽에 (프롬프트 X + 승리 응답 ŷ_W)를 넣어 점수 R(X, ŷ_W)를, 다른 쪽에 (프롬프트 X + 패배 응답 ŷ_L)을 넣어 점수 R(X, ŷ_L)을 얻습니다. 이 두 점수를 함께 쓰는 손실이 필요합니다.

유도: 데이터(선호 쌍들)가 일어날 확률을 최대화하는 파라미터 θ를 찾습니다. 쌍들이 서로 독립이라 보면, n개 쌍 각각의 'W가 L보다 나을 확률'의 곱을 최대화하려 합니다. Bradley-Terry로 이 확률은 σ(R_W − R_L)입니다.

확률의 곱은 매우 작아져 불안정하므로 로그를 취합니다(곱의 최대화 = 로그합의 최대화). 그러면 Σ log σ(R_W − R_L)을 최대화하는 문제가 됩니다. ML에서는 보통 최소화를 선호하니 앞에 음수를 붙여:

손실 = −E[ log σ( R(X, ŷ_W) − R(X, ŷ_L) ) ]

이것이 보상 모델의 손실 함수입니다(음의 로그우도, 곧 일종의 교차 엔트로피).

용어 설명
승리/패배 응답(winning/losing output)
선호 쌍에서 더 나은 / 못한 응답.
음의 로그우도(negative log-likelihood)
데이터가 일어날 확률(우도)에 로그·음수를 취한 손실.
로그를 취하는 이유
확률의 곱이 0에 가까워지는 불안정을 피하고 합으로 다루기 위해.

한국어 번역

핵심 아름다움: 손실은 쌍 비교(pairwise)지만, 보상 모델 자체는 예측에 쌍이 필요 없습니다. 쌍으로 학습하지만, 결국 (프롬프트 하나 + 응답 하나)를 받아 점수 하나를 내는 모델이 됩니다. 학습 결과 승리 예시엔 높은 점수, 패배 예시엔 낮은 점수를 내게 됩니다.

용어 설명
쌍으로 학습, 하나로 추론
손실은 쌍 비교지만, 완성된 보상 모델은 응답 하나에 점수 하나를 냄.

한국어 번역
  • 데이터: 보통 수만(tens of thousands) 개 이상. 라벨은 선호 평가이며, RLHF면 사람이 매긴 것.
  • 모델: 여러 선택지가 있습니다. 요즘은 decoder-only LLM에 분류 헤드를 붙여 점수를 내는 방식이 흔합니다(everything is an LLM). 또는 BERT 같은 encoder-only에서 CLS 토큰 임베딩을 투영할 수도 있습니다. (보상 모델 평가용 벤치마크로 RewardBench가 있음)
  • 차원(dimension): 보상은 특정 차원에 대한 것입니다 — 출력이 친근한가, 안전한가 등. 차원별로 다른 보상 모델을 둘 수도, 종합 점수를 둘 수도 있습니다.
  • 사람 평가의 민감성: 평가자에게 주는 지침(guideline)이 객관적이고 명확해야 잡음이 줄어듭니다.
  • 정규화: 보상의 스케일 자체가 조정됩니다. 추론 시 배치(batch)에 걸쳐 정규화하는 절차가 있습니다. 회귀라기보다 확률적 공식에 가깝게 봅니다(선호 데이터가 낫다/못하다의 1/0이므로 분류적 성격도 있으나, 끝에 보상값을 씁니다).
용어 설명

차원(dimension)
보상이 측정하는 측면(친근함·안전 등).

정규화(normalization)
보상 점수의 스케일을 배치에 걸쳐 맞춤.

💡 현장에서 써먹기
  • 보상이 '차원별(친근·안전 등)'이라는 점은 "AI 품질은 한 숫자가 아니다"를 보여준다. 같은 응답도 친근함·안전성·정확성 등 측면마다 평가가 다르다. AI 도구 품질을 따질 때 단일 점수가 아니라 업무에 중요한 차원별로 봐야 한다는 안목을 준다(Lecture 4 평가 부분과 연결).
  • 사람 평가 지침의 명확성은 "검수 기준을 명문화하라"는 실무 교훈이다. 평가자에게 주는 기준이 모호하면 결과가 잡음투성이가 된다. 사람이 AI 출력을 검수·등급화하는 업무라면, 객관적이고 명확한 기준표를 먼저 만드는 것이 품질을 좌우한다.
