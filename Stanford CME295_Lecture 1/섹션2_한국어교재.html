섹션 2. NLP 개요 — 과제 유형과 평가지표

📄원문 출처: Stanford CME295, Autumn 2025, Lecture 1, 타임스탬프 10:42~21:10

1. 강의 개요

  • 자연어처리(NLP)가 무엇인지 정의하고, NLP 과제를 분류·다중분류·생성 세 가지 유형으로 나눠 설명한다.
  • 각 유형을 대표 과제(감성분석, 개체명 인식, 기계번역)로 예시하고, 어떤 데이터셋을 쓰는지 본다.
  • 과제별 성능을 어떻게 평가하는지 — 정확도·정밀도·재현율·F1, BLEU·ROUGE·perplexity — 를 다룬다.

2. 학습 목표

  1. NLP 과제를 분류 / 다중분류 / 생성 세 유형으로 구분하고 각 대표 과제를 들 수 있다.
  2. 정밀도(precision)·재현율(recall)·F1이 왜 정확도(accuracy)만으로 부족한지(클래스 불균형) 설명할 수 있다.
  3. 생성 과제 평가가 왜 더 어려운지, BLEU·ROUGE·perplexity가 각각 무엇을 보는지 안다.

3. 본문

(...) we can basically classify NLP tasks into three buckets. So the first bucket is what we call classification. So we have an input text as an input. And then what we want is to predict something. (...) The second category is what we call multi-classification. (...) this time we predict more than one thing. (...) 13:07 And then the last bucket, which is very popular these days, is the generation bucket. So you have a text as input. And you also have text as output. And here the length can be variable.

한국어 번역

이제 NLP 전반을 이야기하겠습니다. NLP는 자연어처리(natural language processing)의 약자이고, 텍스트를 다루고 텍스트로 무언가를 계산하는 분야입니다. NLP 과제는 크게 세 가지 묶음으로 분류할 수 있습니다. 첫째는 분류(classification)입니다. 텍스트를 입력으로 받아 무언가를 예측합니다. 둘째는 다중분류(multi-classification)입니다. 이번에는 한 가지가 아니라 여러 가지를 예측합니다. 셋째는 요즘 가장 인기 있는 생성(generation) 묶음입니다. 텍스트를 입력으로 받고 출력도 텍스트인데, 이때 출력 길이는 미리 알 수 없이 가변적입니다.

세 유형의 대표 과제는 다음과 같습니다.

  • 분류: 감성분석(영화평이 긍정/부정/중립인지), 의도 탐지(intent detection, "내일 알람 맞춰줘" → 의도는 '알람 생성'), 언어 감지, 토픽 모델링
  • 다중분류: 개체명 인식(NER), 품사 태깅(part-of-speech tagging), 구문 분석(parsing)
  • 생성: 기계번역, 질의응답(question answering), 요약(summarization), 코드·시 생성 등
용어 설명
NLP(Natural Language Processing, 자연어처리)
텍스트를 다루고 계산하는 분야.
분류(classification)
입력 텍스트에 대해 한 가지 범주를 예측.
다중분류(multi-classification)
한 텍스트에서 여러 항목을 동시에 예측.
생성(generation)
텍스트를 입력받아 길이가 정해지지 않은 텍스트를 출력.
개체명 인식(NER, Named Entity Recognition)
텍스트 안의 특정 단어가 장소·시간 등 어떤 범주에 속하는지 라벨링하는 과제.
의도 탐지(intent detection)
사용자가 무엇을 하려는지 파악하는 과제.

블록 2분류 과제와 평가지표 (정확도·정밀도·재현율·F1)

▸ 영문 원문 보기

14:21 we're going to start with the first bucket, which is the classification bucket. And here we're going to illustrate this with the sentiment extraction task. So let's suppose we have a sentence, "This teddy bear is so cute." We want our model to predict (...) a positive sentiment. (...) you have accuracy, which is (...) what is the percentage of the observations that you correctly predicted? (...) one is precision. Which is out of all the positive predictions that you made which ones were correct? And then the second one is recall. Out of all the true labels how many of them did you correctly predict as being positive? And you have this metric called the F1 score, which basically takes the harmonic mean of precision and recall. (...) 15:55 sometimes you have tasks and data sets where your classes are very imbalanced. (...) you can have 99% of your data set that is positive label and then only 1% (...) negative. And so here if you take a metric like accuracy it would be very misleading.

한국어 번역

첫 번째 묶음인 분류부터 시작하겠습니다. 감성 추출(sentiment extraction) 과제로 예를 들겠습니다. "This teddy bear is so cute(이 곰인형 정말 귀엽다)"라는 문장이 있으면, 모델이 이를 긍정 감성으로 예측하길 바랍니다. 데이터셋으로는 IMDb 영화평, 아마존 상품평, X(옛 트위터) 게시물 등을 씁니다.

평가지표는 다음과 같습니다.

  • 정확도(accuracy): 전체 중 올바르게 예측한 비율.
  • 정밀도(precision): 긍정이라고 예측한 것들 중 실제로 맞은 비율.
  • 재현율(recall): 실제 긍정 라벨 중 긍정으로 올바르게 예측한 비율.
  • F1 점수(F1 score): 정밀도와 재현율의 조화평균(harmonic mean)으로, 두 값을 하나의 수치로 요약.

왜 이렇게 여러 지표가 필요할까요? 클래스가 심하게 불균형한 데이터셋이 있기 때문입니다. 예를 들어 데이터의 99%가 긍정이고 1%만 부정이라면, 정확도는 매우 오해를 부릅니다. 모든 것을 다수 클래스(긍정)로만 예측해도 정확도가 99%로 나오지만, 좋은 분류기가 아니기 때문입니다. 그래서 정밀도와 재현율이 중요한 역할을 합니다.

용어 설명
감성 추출/감성분석(sentiment extraction/analysis)
텍스트의 감정이 긍정·부정·중립인지 예측하는 과제.
정밀도(precision)
예측한 양성 중 실제 양성 비율. "잘못 짚지 않았는가."
재현율(recall)
실제 양성 중 찾아낸 비율. "놓치지 않았는가."
F1 점수
정밀도·재현율의 조화평균. 한쪽만 높은 경우를 걸러낸다.
클래스 불균형(class imbalance)
한 범주가 데이터 대부분을 차지하는 상황. 정확도를 왜곡한다.

16:43 let's move to the second category of NLP tasks. So this one is the multi-classification category. So you have an input text and you predict multiple things. And we're illustrating this with the NER task. Which (...) is about identifying the category of given words. (...) we want to identify teddy bear as being an entity. (...) you would use classification metrics, but not at the sentence level, but more either at the token level or at the entity type level.

한국어 번역

두 번째 유형은 다중분류입니다. 입력 텍스트 하나에서 여러 항목을 예측합니다. 개체명 인식(NER)으로 예를 들겠습니다. NER은 주어진 단어가 어떤 범주에 속하는지 식별하는 과제입니다. 예를 들어 "teddy bear(곰인형)"를 하나의 개체(entity)로 식별하려는 것입니다.

평가는 분류 지표를 쓰되, 문장 단위가 아니라 토큰(token) 단위나 개체 유형(entity type) 단위로 측정합니다. 예를 들어 '장소'라는 범주가 있으면, 그 범주에 속하는 단어들을 얼마나 잘 예측하는지 그 범주 기준으로 지표를 집계합니다.

용어 설명
토큰(token)
텍스트를 자른 단위. (다음 섹션에서 자세히 다룸)
개체 유형(entity type)
장소·시간·인물 등 개체의 범주.

다중분류 평가는 "문장 하나가 맞았나"가 아니라 "토큰/범주별로 얼마나 맞혔나"로 본다는 점이 핵심.

Which stands for workshop on machine translation. (...) 18:38 to evaluate the performance of your model is actually a lot more tricky. Because (...) you can have many different ways to translate something. (...) one that you may have heard is BLEU. BLEU stands for bilingual evaluation under study. And it is a measure of how well your translation stands with respect to a reference text. Same story for ROUGE. (...) 20:00 the problem with these metrics is that you always need a reference text. (...) having labels is very cost expensive. (...) we can actually forego of these reference-based metrics and go towards a more reference-free metrics (...) 20:43 the last metric (...) is called perplexity. And perplexity only looks at the probabilities that are output by the model. And it basically quantifies how surprised the model is by its outputs. So blue and rouge, the higher the better. perplexity, the lower the better.

한국어 번역

마지막 유형은 텍스트를 입력받아 텍스트를 출력하는 생성입니다. 기계번역(machine translation)으로 예를 들겠습니다. 출발어(source language)를 도착어(target language)로 번역하는 과제입니다. 생성 과제는 텍스트 쌍(pair)이 필요해서 데이터셋 구하기가 더 어렵습니다. 대표적으로 WMT(Workshop on Machine Translation) 데이터셋이 있고, 유럽의회 회의록에서 가져온 영어-프랑스어, 영어-독일어 등 짝지어진 문장들을 담고 있습니다.

생성 과제의 성능 평가는 훨씬 까다롭습니다. 같은 내용을 번역하는 방법이 여러 가지이기 때문입니다. 과거에는 규칙 기반 지표를 썼습니다.

  • BLEU: bilingual evaluation under study의 약자. 번역 결과가 참조 텍스트(reference text)와 얼마나 일치하는지 측정. (높을수록 좋음)
  • ROUGE: 여러 지표의 묶음으로, 같은 것을 다른 방식으로 측정. (높을수록 좋음)
  • perplexity(혼란도): 모델이 출력한 확률만 보고, 모델이 자기 출력에 얼마나 '놀라는지'를 정량화. (낮을수록 좋음)

BLEU·ROUGE의 문제는 항상 참조 텍스트, 즉 라벨이 필요하다는 점입니다. 라벨을 만드는 데는 시간과 비용이 많이 듭니다. 강의 후반에 다루겠지만, LLM의 발전 덕분에 이제는 참조 텍스트가 필요 없는(reference-free) 평가 방식으로 갈 수 있습니다.

⚠️ 참고

참고: 강사는 "BLEU는 프랑스어로 파랑, ROUGE는 빨강을 뜻한다"는 점을 언급했는데, 이는 명칭에 관한 여담이다. (기술 내용 아님)

용어 설명
기계번역(machine translation)
출발어를 도착어로 번역하는 생성 과제.
출발어/도착어(source/target language)
번역의 원문 언어 / 결과 언어.
참조 텍스트(reference text)
정답으로 비교하는 기준 번역문(=라벨).
BLEU
번역이 참조문과 얼마나 일치하는지 보는 규칙 기반 지표(높을수록 좋음).
ROUGE
일치도를 측정하는 지표 묶음(높을수록 좋음).
perplexity(혼란도)
모델 출력 확률만으로 측정하는 지표. 모델이 출력에 얼마나 놀라는지(낮을수록 좋음).
reference-free(참조 비의존) 평가
정답 라벨 없이 성능을 평가하는 방식.

부록. 실무 적용 포인트 (NLP·LLM 기술 내용 한정)

💡 현장에서 써먹기
  • 분류(classification)는 민원·문서 자동 분류에 바로 대응된다. 들어온 민원 텍스트를 부서·유형별로 자동 분류하거나, 정책에 대한 주민 반응(긍정/부정)을 감성분석으로 모니터링하는 식으로 쓸 수 있다.
  • 개체명 인식(NER)은 문서에서 핵심 정보 추출에 쓸 수 있다. 공문·보고서·계약서에서 지명·날짜·기관명·금액 같은 항목을 자동으로 뽑아내 정리하는 작업에 해당한다.
  • 생성(generation)은 요약·번역·초안 작성이다. 긴 보고서 요약, 외국어 자료 번역, 공문 초안 생성 등이 모두 이 유형이며, ChatGPT류 도구가 잘하는 영역이다.
  • AI 도입 성과를 '정확도 한 숫자'로만 믿지 말 것. 클래스 불균형이 있으면 정확도는 부풀려진다. 민원 자동분류 같은 도구의 성능을 검토할 때는 정밀도·재현율(또는 F1)을 함께 봐야 실제 쓸만한지 판단할 수 있다.
