## 섹션 3. 분산 학습 — GPU 메모리와 병렬화

> 원문 출처: Stanford CME295, Autumn 2025, Lecture 4, 타임스탬프 (24:45)~(37:54)

---

## 1. 강의 개요

- 거대 모델 학습에 필요한 하드웨어(GPU)와, 학습 과정에서 메모리에 저장해야 하는 것들(활성값·기울기·옵티마이저 상태)을 본다.
- GPU 한 장의 메모리 한계를 넘기 위한 데이터 병렬화(data parallelism)와 그 최적화 ZeRO를 다룬다.
- 모델 자체를 쪼개는 모델 병렬화(model parallelism) — 전문가·텐서·파이프라인 병렬화 — 를 개관한다.

---

## 2. 학습 목표

1. 학습의 순전파·역전파에서 메모리에 무엇을(활성값·기울기·옵티마이저 상태) 저장하는지 안다.
2. 데이터 병렬화와 ZeRO(중복 제거)가 메모리를 어떻게 줄이는지, 그 대가(통신 비용)는 무엇인지 설명할 수 있다.
3. 모델 병렬화의 세 종류(전문가·텐서·파이프라인)를 개념적으로 구분할 수 있다.

## 3. 본문

### 블록 1 — 학습 단계와 저장해야 하는 것들

**영문 원문**
> (25:46) what is the kind of hardware that loves matrix multiplications? GPUs. (...) Google (...) developed their own hardware that's called TPUs. (...) (26:50) you have one step called the forward pass (...) you have something that's called activations which are basically the values at each layer that are needed in order to compute the loss. (...) (28:26) another pass called backwards pass (...) the gradient (...) gradients they also need to be saved (...) (29:27) (Adam) optimizer (...) the first moment and the second moment (...) you also need to (...) save them.

**한국어 번역**
LLM 학습에는 행렬 곱셈이 많아 GPU가 필요합니다(여러 장 필요). 구글은 자체 하드웨어 TPU를 만들었지만, 비구글 모델은 대개 GPU로 학습됩니다.

학습 한 단계는 이렇습니다.
1. **순전파(forward pass)**: 데이터를 모델에 통과시킵니다. 이때 활성값(activation) — 손실 계산에 필요한 각 층의 값 — 이 생깁니다. 손실(loss)은 정답(라벨)에서 얼마나 벗어났는지를 나타냅니다.
2. **역전파(backward pass)**: 손실을 최소화하는 방향, 즉 각 파라미터에 대한 손실의 기울기(gradient)를 계산합니다.
3. **가중치 갱신**: 기울기 방향으로 가중치를 갱신합니다. 보통 Adam 옵티마이저를 쓰는데, 기울기의 이동평균인 1차·2차 모멘트(moment)를 추가로 추적합니다.

메모리에 저장해야 하는 것: 활성값, 기울기, 옵티마이저 상태(모멘트). 활성값 메모리는 모델 크기, 배치 크기, 컨텍스트 길이(self-attention의 O(N²) 때문)에 따라 커집니다.

**용어 설명**
- **GPU / TPU**: 행렬 연산용 하드웨어. TPU는 구글 자체 칩.
- **순전파(forward pass)**: 입력→출력 계산 단계. 활성값 생성.
- **활성값(activation)**: 손실 계산에 필요한 각 층의 중간 값.
- **역전파(backward pass)**: 손실의 기울기를 계산하는 단계.
- **기울기(gradient)**: 손실을 줄이는 방향. 파라미터별로 계산.
- **Adam 옵티마이저**: 기울기의 1차·2차 모멘트를 활용해 가중치를 갱신하는 표준 방법.

### 블록 2 — GPU 메모리의 한계와 데이터 병렬화

**영문 원문**
> (30:00) Memory is not unlimited. (...) H100 (...) GPU memory (...) 80 gig (...) on the order of tens of gigabytes. (...) (31:03) data parallelism also known as DP (...) divide the batch of data across devices (...) you need to have a copy of the model per device (...) you're able to reduce the memory that is linked to the batch size. (...) (32:07) the gradient is just the average of the gradients (...) you have some communication in between the GPUs that (...) aggregate the gradient. (...) (32:37) an additional cost which is called communication cost (...) your training is going to be slower.

**한국어 번역**
메모리는 무한하지 않습니다. 좋은 GPU인 H100도 메모리가 80GB(수십 GB 규모)뿐입니다. 저장할 게 그렇게 많은데 80GB는 부족합니다. 그래서 GPU 한 장이 아니라 여러 장에 부하를 나눕니다.

첫 번째 방법은 데이터 병렬화(data parallelism, DP)입니다. 데이터 배치(batch)를 여러 장치(GPU)에 나눠, 순전파·역전파를 병렬로 합니다. 이때 각 장치마다 모델 사본(copy)이 필요합니다(활성값 등을 계산해야 하므로). 이렇게 하면 배치 크기와 관련된 메모리를 줄일 수 있습니다.

- 기울기는 어떻게? 각 GPU의 기울기를 평균 냅니다. GPU 간에 통신해 기울기를 취합합니다.
- 한계: ① 모델 하나는 GPU 한 장에 들어가야 합니다(데이터 병렬화는 모델을 쪼개지 않음). ② GPU 간 취합을 위한 통신 비용(communication cost)이 추가돼 학습이 느려집니다.

**용어 설명**
- **데이터 병렬화(data parallelism, DP)**: 데이터 배치를 여러 GPU에 나눠 병렬 처리. 각 GPU에 모델 사본 필요.
- **배치(batch)**: 한 번에 처리하는 데이터 묶음.
- **통신 비용(communication cost)**: GPU 간 데이터(기울기 등)를 주고받는 데 드는 비용. 학습을 느리게 함.

### 블록 3 — ZeRO: 중복 제거 최적화

**영문 원문**
> (33:42) a lot of duplication (...) this method is called zero (...) redundancy optim(ization) (...) on each GPU you store the same parameters, the same gradients, the same optim(izer) (...) states. So (...) how about we shard (...) partition those quantities across GPUs. (...) (34:12) sharing the optim(izer) states (...) we can also partition the gradients and (...) the (parameters). (...) (34:43) you're going to have even more communication costs, but (...) it allows (...) to decrease the memory load. (...) there's 0 1, 02, 03.

**한국어 번역**
데이터 병렬화에서는 각 GPU가 같은 파라미터·기울기·옵티마이저 상태를 똑같이 저장합니다 — 중복(duplication)이 많습니다. 이 중복을 없애려는 기법이 ZeRO(Zero Redundancy Optimizer, 영(零)중복 옵티마이저)입니다. 발상은 — 이 양들을 GPU에 걸쳐 분할(shard/partition)하자는 것입니다.

- **ZeRO-1**: 옵티마이저 상태를 분할. (메모리 크게 절약)
- **ZeRO-2**: 기울기도 분할.
- **ZeRO-3**: 파라미터도 분할. (중복 정보 없이 전부 분할)

대가는 통신 비용이 더 늘어나는 것이지만, GPU별 메모리 부담은 크게 줍니다. 어느 단계(ZeRO-1/2/3)를 고를지는 학습 시간 민감도와 모델 크기에 달려 있습니다.

**용어 설명**
- **ZeRO(Zero Redundancy Optimizer)**: 파라미터·기울기·옵티마이저 상태를 GPU에 분할해 중복을 없애는 기법.
- **분할/샤딩(shard/partition)**: 한 덩어리를 여러 GPU에 나눠 저장.
- **ZeRO-1/2/3**: 옵티마이저 상태 / +기울기 / +파라미터 까지 분할하는 단계.

### 블록 4 — 모델 병렬화: 전문가·텐서·파이프라인

**영문 원문**
> (35:46) another set of methods that's called model parallelism (...) (36:18) MOE based LLM (...) expert parallelism which is (...) having one expert on a device another one on another (device). (...) (36:51) tensor parallelism is (...) when you have big matrix multiplications to (...) cut that in a way that decreases the memory. (...) (37:19) pipeline parallelism (...) one GPU is going to only be responsible for (...) layers 1 2 3 and then another one (...) four five six.

**한국어 번역**
데이터 병렬화는 '데이터'를 나눴습니다. 반면 모델 병렬화(model parallelism)는 모델의 연산 자체를 한 배치 안에서도 나눕니다. 여러 방법이 있는데 세 가지만 짚습니다.

- **전문가 병렬화(expert parallelism)**: MoE에서 전문가들을 서로 다른 장치에 배치(한 전문가는 이 GPU, 다른 전문가는 저 GPU). (Lecture 3의 MoE와 연결)
- **텐서 병렬화(tensor parallelism)**: 큰 행렬 곱셈을 쪼개 GPU별 메모리 요구를 줄임.
- **파이프라인 병렬화(pipeline parallelism)**: 순전파의 층들을 나눠, 한 GPU는 1~3층, 다른 GPU는 4~6층을 담당.

> 세부까지 외울 필요는 없고, "데이터를 나누는 병렬화(DP/ZeRO)와 모델을 나누는 병렬화(MP)가 있다"는 큰 그림이 중요합니다.

**용어 설명**
- **모델 병렬화(model parallelism, MP)**: 모델의 연산을 여러 GPU에 나눔.
- **전문가 병렬화(expert parallelism)**: MoE 전문가를 GPU별로 분산.
- **텐서 병렬화(tensor parallelism)**: 큰 행렬 곱을 쪼갬.
- **파이프라인 병렬화(pipeline parallelism)**: 층을 GPU별로 분담.

## 부록. 실무 적용 포인트 (NLP·LLM 기술 내용 한정)

- **GPU 메모리 한계와 병렬화는 "왜 LLM 학습·운영에 GPU가 여러 대 필요한가"의 답이다.** 모델 하나가 GPU 한 장에 안 들어가기 때문에 쪼개 나눈다. 자체 모델 학습·미세조정을 검토할 때 'GPU 몇 장이 필요한가'가 비용의 핵심이며, 이는 모델 크기에 직결된다.
- **통신 비용이라는 트레이드오프는 "GPU를 늘린다고 선형으로 빨라지지 않는다"를 설명한다.** GPU를 늘릴수록 메모리는 확보되지만 GPU 간 통신이 늘어 속도 이득은 줄어든다. 인프라 견적에서 'GPU 수 = 속도'로 단순 환산하면 안 된다는 안목을 준다.
