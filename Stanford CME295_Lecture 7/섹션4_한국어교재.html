섹션 4. 도구 호출 (Tool/Function Calling)

📄원문 출처: Stanford CME295, Autumn 2025, Lecture 7, 타임스탬프 57:18~1:20:38

1. 강의 개요

  • 구조화된 데이터·외부 시스템과 연결하는 도구 호출(tool calling)·함수 호출(function calling)을 다룬다.
  • 함수 정의(설명·입력·출력)와, LLM이 도구를 쓰는 3단계 메커니즘(인자 채우기 → 함수 실행 → 자연어 응답)을 본다.
  • 도구 호출을 학습시키는 두 길 — SFT 쌍, 그리고 추론 기반 설명(explanation) — 을 설명한다.

2. 학습 목표

  1. 도구 호출/함수 호출이 무엇이며 RAG와 어떻게 다른지(구조화 데이터·행동) 설명할 수 있다.
  2. LLM이 도구를 쓰는 3단계(인자 추론 → 실행 → 자연어 응답)를 안다.
  3. 도구 호출을 SFT로 학습하는 법과, 추론 기반 설명으로 대체하는 법을 이해한다.

3. 본문

한국어 번역

RAG는 비구조화 데이터(문서·글)를 다뤘습니다. 도구 호출은 구조화된(structured) 데이터·외부 시스템을 다룹니다. 구조화 데이터는 표(테이블)로 볼 수 있고, 이는 함수(function)로 다시 표현할 수 있습니다 — 입력(인자)을 받아 출력을 내는 관계. 그래서 도구 호출(tool calling)을 함수 호출(function calling)이라고도 합니다. (LLM은 읽기 쉬워 보통 Python을 쓰지만 다른 언어도 가능)

정의(IBM 기사 인용): "도구 호출은 자율 시스템이 외부 자원에 동적으로 접근하고 작동해 복잡한 과제를 완수하게 한다." 핵심 둘 — ① 과제 완수, ② 외부 자원 활용(필수는 아니나, 사전학습 LLM의 지식 공백을 메우는 길).

예: "내 근처 곰인형 찾아줘" — 도구 없는 LLM은 실시간 재고를 몰라 "모르겠다"고 답합니다. 도구를 쓰면 필요한 정보를 주입해 답하게 할 수 있습니다.

용어 설명
도구 호출/함수 호출(tool/function calling)
LLM이 외부 함수·API를 불러 과제를 수행하게 하는 것.
구조화 데이터(structured data)
표처럼 입력-출력 관계가 정해진 데이터. (RAG의 비구조화 문서와 대비)
외부 자원(external resource)
API·DB 등 모델 밖의 자원. 지식 공백을 메움.

한국어 번역

함수 정의 예: find_teddy_bear라는 함수를, 위치에 따라 어떤 API를 호출해 주변 곰인형을 가져오게 정의합니다. 함수 호출에 담기는 것:

  • 문서화(description): API의 입력·출력을 문서화해, 모델이 이 함수가 무엇을 위한 것인지 알게 합니다(설명이 결정적).
  • 백엔드 호출: 정의의 핵심 — 위치로 API를 질의해 가능한 곰인형을 가져옵니다.
  • 구조화된 출력: 반환값은 (클래스 등으로) 구조화돼 있어 모델이 anchor(기준)로 삼을 수 있습니다.

중요: 이 모든 것은 개발자가 보는 것이고, LLM이 보는 것은 다릅니다. LLM은 함수 API·입력·출력·문서화의 요지만 봅니다. 구현 세부(implementation)는 코드베이스에 있을 뿐 LLM은 못 봅니다.

용어 설명
함수 정의(function definition)
함수의 설명·입력·출력·구현. LLM은 구현은 못 보고 시그니처·설명만 봄.
문서화/설명(description)
함수 용도 설명. 모델이 도구를 이해하는 핵심.
구조화된 출력
모델이 해석할 수 있게 정리된 반환값.

한국어 번역

LLM이 도구를 쓰는 과정은 3단계입니다.

  1. 인자 추론(LLM): 함수와 관련된 질문을 하면, 함수 API(구현 제외)를 프롬프트 앞부분(preamble)에 넣습니다. LLM의 역할은 함수 구현을 추론하는 게 아니라, 사용자 질의에 맞는 올바른 인자(argument)를 함수에 채우는 것입니다. (예: 위치 권한이 켜져 있으면 LLM이 맥락에서 스탠퍼드 좌표를 인자로 채움)
  2. 함수 실행(LLM 무관): 채워진 인자로 함수를 실제 실행합니다. 이건 LLM과 무관한 코드 실행으로, 구조화된 답(곰인형 이름·위치 등)을 얻습니다.
  3. 자연어 응답(LLM): 그 구조화된 답을 다시 LLM에 줘, JSON 같은 형태가 아니라 자연어 응답을 생성하게 합니다.
용어 설명
3단계 메커니즘
①인자 추론(LLM) → ②함수 실행(코드) → ③자연어 응답(LLM).
preamble(프리앰블)
프롬프트 앞부분. 함수 API를 여기 둠.
인자(argument)
함수에 넣는 입력값. LLM이 질의에서 추론해 채움.

한국어 번역

도구 호출은 어떻게 학습시킬까요?

SFT 방식(두 쌍):

  1. 첫 LLM 호출 학습: 함수 정의 + 질의 패턴을 인식해 올바른 인자에 연결하도록 SFT.
  2. 둘째 LLM 호출 학습: 도구의 (구조화된) 답을 원하는 형식의 자연어 응답으로 매핑하도록 SFT. 이때 입력은 단순 JSON이 아니라 대화 이력 전체(초기 질의·도구 호출·결과)라 더 깁니다. SFT 예시는 다양·대표적이어야 합니다(위치를 직접 주는 경우, 멀티턴 등).

추론 기반 설명 방식: 요즘 모델은 코드·추론을 잘해서, SFT 없이 설명(explanation)만으로 도구 사용을 가르칠 수 있습니다. 다만 좋은 설명 프롬프트를 사람이 직접 쓰긴 어렵습니다. 그래서 — SFT 쌍들을 평가셋(원하는 동작)으로 두고, 현재 프롬프트를 그 평가셋에 돌려 성공·실패를 봅니다("파리에서 곰 찾기"는 실패 등). 그 결과를 추론 모델에 되먹여 설명을 자동으로 다듬게 합니다. 이는 학습 시점(offline)에 하는 일로, 다듬은 고정 설명을 함수 API와 함께 두면 추론 시 어떤 질의에도 도구를 쓸 줄 압니다. (직접 끝까지 쓰지 말고, 초안만 주고 강력한 모델에 맡기길 권함)

용어 설명
SFT 두 쌍
인자 추론 학습 + 자연어 응답 학습.
대화 이력(conversation history)
질의·도구 호출·결과 전체. 둘째 SFT의 입력.
추론 기반 설명(explanation)
SFT 대신, 자동으로 다듬은 설명 프롬프트로 도구 사용을 가르치는 법.

부록. 실무 적용 포인트 (NLP·LLM 기술 내용 한정)

💡 현장에서 써먹기
  • 도구 호출은 "LLM이 실제 시스템·데이터와 일하게 하는" 핵심이다. 단순 텍스트 생성을 넘어, 실시간 정보 조회·계산·기존 시스템 연동이 가능해진다. 봉화군의 내부 DB·행정 시스템·외부 API(날씨·교통 등)와 LLM을 잇는 기술적 토대로, 단순 챗봇을 넘어선 업무 자동화의 출발점이다.
  • 'LLM은 함수 구현을 못 보고 설명·시그니처만 본다'는 점은 보안·설계의 핵심이다. 모델은 무엇을 할 수 있는지(인터페이스)만 알고 내부 구현·민감 로직은 모른다. AI에 기능을 열어줄 때 '무엇을 노출하고 무엇을 감출지'를 인터페이스 단에서 통제할 수 있다는 의미다.
  • '추론 기반 설명을 모델이 다듬게 한다'는 발상은 프롬프트 작성에 직접 쓰인다. 좋은 지시문을 사람이 처음부터 쓰기 어렵다면, 잘되는·안되는 사례를 모아 강력한 모델에 "어떻게 고치면 좋아질지" 물어 개선하는 방법이 효율적이다.
