섹션 6. 벤치마크와 모델 선택

📄원문 출처: Stanford CME295, Autumn 2025, Lecture 8, 타임스탬프 1:23:26~(1:49:08, 끝)

1. 강의 개요

  • LLM을 비교하는 표준인 벤치마크를 범주별로 본다 — 지식(MMLU)·추론(AIME·PIQA)·코딩(SWE-bench)·안전(HarmBench)·에이전트(τ-bench).
  • 에이전트 벤치마크의 pass^k(모든 K 시도 성공 확률)와 그 동기를 다룬다.
  • 실제 모델 선택 — Pareto 프런티어, 데이터 오염(contamination), Goodhart's law, 그리고 "직접 써보라"는 조언으로 마무리한다.

2. 학습 목표

  1. 벤치마크 범주(지식·추론·코딩·안전·에이전트)와 대표 예를 짝지을 수 있다.
  2. 안전 벤치마크가 왜 모델 간 직접 비교에 부적합한지, 에이전트 평가의 pass^k가 무엇인지 안다.
  3. Pareto 프런티어·데이터 오염·Goodhart's law를 이해하고, 모델 선택에 적용할 수 있다.

한국어 번역

오늘날 벤치마크는 몇 가지 범주에 있습니다.

지식 기반 벤치마크: 모델이 사실을 잘 복원하는지(여러 분야에 걸쳐) 봅니다. 주로 사전학습이 얼마나 잘 됐는지를 잽니다. 대표는 MMLU(Massive Multitask Language Understanding) — 법·의학 등 약 60개 다양한 과제로, 자유 형식이 아니라 4지선다입니다(LLM에게 정답 글자를 출력하게 해 하드코딩으로 추출·대조). 자유 형식 + LLM 심판은 또 다른 오류층을 더하므로, 벤치마크는 보통 이렇게 정답 추출을 제약합니다.

추론 벤치마크: 답 전에 사고가 필요한 것들.

  • AIME: 올림피아드 준비 고교생이 보는 어려운 수학 시험. 답을 세 자리 숫자로 쓰게 해 LLM 친화적(하드코딩 채점 가능).
  • PIQA(Physical Interaction QA): 일상 물리 상식 추론. MMLU(4지선다)와 달리 2지선다, 약 2만 예시. 예: "카펫에서 잃어버린 물건 찾기 — 밀폐 흡입구 진공 vs 망 씌운 진공" → 망이면 흡입하며 물건이 망에 걸림. 수학이 아닌 일상 상식.
용어 설명
MMLU
약 60과제 4지선다 지식 벤치마크. 사전학습 품질 반영.
AIME
어려운 수학 추론 벤치마크(세 자리 숫자 답).
PIQA
물리 상식 추론 2지선다 벤치마크.
하드코딩 채점
정답을 글자·숫자로 제약해 자동 추출·대조.

한국어 번역

코딩 벤치마크: 모델이 복잡한 코딩 문제를 푸는지 봅니다(① AI 코딩 보조용, ② 에이전트의 도구가 Python이라 코드 읽기·쓰기 능력 필요). 대표는 SWE-bench(Software Engineering benchmark 추정) — 인기 Python 저장소에서 '이슈를 고치고 테스트를 추가한 PR'을 골라, 수정 전엔 테스트 실패·수정 후엔 통과라는 점을 이용합니다. 모델에게 GitHub 이슈를 풀게 하고, 패치 전후 테스트 상태로 평가합니다(테스트 주도 개발과 같은 원리).

안전 벤치마크: 보통 모델 광고엔 안 나옵니다 — 안전 정책은 제공자마다 달라(주관적), 같은 벤치마크 점수를 모델 간 비교하기 어렵기 때문. 모델 카드의 안전 섹션은 '한 일'을 적을 뿐 모델 비교는 잘 안 합니다. 대표는 HarmBench(Harmful behavior benchmark 추정) — 네 범주(표준 유해행동, 저작권, 맥락형(텍스트), 멀티모달). 유해 문장은 정규식으로 못 잡으므로 분류기로 평가합니다. 흥미로운 점: 모델 품질과 안전을 분리해, 모델이 유해 행동을 시도하면(성공 못 해도) 공격 성공으로 칩니다. (이 벤치마크는 분류기 기반이라 그 자체로 오류 가능성이 있는, 본 강의 유일한 예)

용어 설명
SWE-bench
GitHub 이슈 수정을 테스트 통과로 평가하는 코딩 벤치마크.
HarmBench
유해 행동 네 범주를 분류기로 평가하는 안전 벤치마크.
안전 벤치마크의 비교 한계
정책이 제공자마다 달라 모델 간 직접 비교가 부적합.

한국어 번역

에이전트 벤치마크: 도구로 풀 수 있는 것 외에 에이전트 행동을 평가합니다. 대표는 τ-bench(타우-벤치, tau = tool-agent-user) — 항공·소매 두 분야에서 도구 집합과 정책(에이전트가 할 수 있는/없는 것)을 주고, 과제(사용자가 에이전트로 달성할 목표)를 줍니다. 특징: 사용자 상호작용이 언어모델로 시뮬레이션됩니다 — 다음 턴이 이전에 의존하므로 하드코딩할 수 없어, 별도 큰 모델이 사용자 역할을 합니다. 항공편 변경 같은 과제를, 데이터베이스가 목표 상태가 됐는지(보상)로 평가합니다.

pass^k: 지난 강의의 pass@k(K 시도 중 적어도 하나 성공)에 빗댄 말장난으로, pass^k는 'K 시도가 모두 성공할 확률'입니다. 왜 중요한가 — 항공·소매 같은 곳에서 에이전트를 자동화하려면 신뢰성·일관성이 중요합니다. 한 번만 맞으면 되는 게 아니라 매번 맞아야 하므로, '적어도 한 번'(pass@k)이 아니라 '모두 성공'(pass^k)이 적절합니다. (유도는 Lecture 6 pass@k 유도 참고)

용어 설명
τ-bench(타우-벤치)
도구·정책·과제로 에이전트를 평가. 사용자를 LLM으로 시뮬레이션.
pass^k
K 시도가 '모두' 성공할 확률. 신뢰성·일관성 측정. (pass@k는 '적어도 하나')

한국어 번역

마무리: 벤치마크는 LLM의 프로필을 그리는 도구입니다. 전부 좋거나 나쁜 모델은 없고, 강·약점이 있어 상황마다 맞는 모델이 다릅니다. (강사 경험: Claude Sonnet은 코딩에 강하고, 빠르고 싼 출력엔 Gemini Flash가 좋음 — 일반 권장이 아니라 개인 경험)

  • Pareto 프런티어(Pareto frontier): 성능을 다른 축(예: 가격)과 함께 그리면, 주어진 가격에서 최선인 모델들의 경계가 그려집니다. 비용·안전·컨텍스트 길이 등 여러 축으로 프런티어를 볼 수 있습니다.
  • 데이터 오염(data contamination): 벤치마크는 모델이 그 정답을 본 적 없어야 의미가 있습니다. 그래서 해시값으로 점검하거나(도구 사용 평가에선 특정 사이트 차단 목록 사용), 수학은 모델이 못 본 새 시험으로 평가하는 게 좋습니다.
  • Goodhart's law(굿하트 법칙): "측정값이 목표가 되면 더 이상 좋은 측정이 아니다." 벤치마크 점수도 진짜 원하는 것에 비춰 가늠해야 하며, 점수가 곧 '나에게 좋은 모델'을 뜻하진 않습니다.

결론: Chatbot Arena 같은 실사용 평가도 한 방법이지만, 궁극적으로는 직접 여러 모델을 써보고 자기 업무에 맞는 것을 골라야 합니다.

용어 설명
Pareto 프런티어
두 축(예: 성능·가격)에서 최선인 모델들의 경계.
데이터 오염(data contamination)
모델이 벤치마크 정답을 미리 학습한 문제. 해시·차단목록·새 시험으로 방지.
Goodhart's law(굿하트 법칙)
측정이 목표가 되면 측정의 의미가 퇴색.

부록. 실무 적용 포인트 (NLP·LLM 기술 내용 한정)

💡 현장에서 써먹기
  • 벤치마크 범주는 "어떤 모델이 어떤 일에 강한지" 읽는 안목을 준다. 지식·추론·코딩·안전·에이전트 점수를 구분해 보면, 업무 성격(사실 조회냐, 계산이냐, 코드냐)에 맞는 모델을 고를 수 있다. 단, 점수 하나로 '최고 모델'을 정하지 말 것.
  • Pareto 프런티어는 "성능만이 아니라 비용·속도와 함께 보라"는 실무 기준이다. 같은 가격대에서 최선인 모델, 같은 성능에서 가장 싼 모델을 찾는 관점이다. 예산이 있는 기관 업무에서 '성능 대비 비용'으로 모델을 고르는 직접적 틀이다.
  • 데이터 오염·Goodhart's law는 "벤치마크 1등을 맹신하지 말라"는 경고다. 모델이 벤치마크 정답을 미리 봤을 수 있고, 점수 자체가 목표가 되면 실제 유용성과 어긋난다. 결국 자기 업무 샘플로 직접 시험해 보는 것이 가장 확실한 평가다 — 모든 AI 도입 결정의 최종 원칙.
